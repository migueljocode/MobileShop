- What was implemented (plan Step 1 scope only):
  - **`AccountDataService`: `IUserRepo` -> `IBaseRepo<User>`.** Lookups moved to generic predicates via a new `UsernameEquals(string)` helper that reproduces the old repository's **case-insensitive** match (`Username.ToLower() == username.ToLower()`) — the old `UserRepo.FindByUsername*` was case-insensitive, so a plain `==` would have silently regressed login. `EnsureAdminUser` now uses `users.Find(...)` and still throws the **same `InvalidOperationException`** when the admin is missing. `GetAdminUsernameAsync` uses `SelectFirstAsync(predicate, orderBy, selector)` returning the username string only (no `User` entity crosses out). `ChangePasswordAsync` now finds the user, hashes, and calls `UpdateAsync`, logging the same warning/information messages and returning `false` when the user is unknown.
  - **`ReportsDataService`: `ITransactionRepo` -> `IBaseRepo<Transaction>`, `IEmployeeRepo` -> `IBaseRepo<Employee>`.** `GetEarliestTransactionDateAsync` now uses the generic ordered `SelectFirstAsync(transaction => !transaction.IsDeleted, t => t.Date, t => (DateTime?)t.Date)`. **The explicit `!IsDeleted` filter is deliberate and load-bearing**: `IBaseRepo<T>` applies no soft-delete filter of its own (verified in `BaseRepo`), whereas the replaced `TransactionRepo.GetEarliestTransactionDateAsync` did filter it — omitting it would have changed which date is returned. `GetDistributionRowsAsync` uses a generic projection selecting `Id` + `PersonNavigation.FirstName/LastName` for active employees, ordered by name to mirror the old `FindAllActiveAsync`, then hands the calculator `Employee` instances carrying the person name — because `DistributionCalculator` matches required employees by exact full name off `PersonNavigation`.
  - **No report or distribution rule changed** — percentages, floor rounding, loss-period handling, ordering, and all exception messages are untouched (L6).
  - **Tests retargeted** from `UserRepo`/`TransactionRepo`/`EmployeeRepo` to `BaseRepo<User>`/`BaseRepo<Transaction>`/`BaseRepo<Employee>`. All 17 existing assertions preserved; **3 focused regressions added** because the generic projection genuinely exposed those gaps: earliest date ignores soft-deleted transactions; inactive required employees are rejected by the distribution; credential lookups are case-insensitive in both directions.
